The first release of Plutonium, a web-based desktop environment for Linux: the desktop is a web page, and native apps (Wayland and X11) and real Chromium tabs are elements in it. It's a public beta. Its developer uses it every day, but it's new to everyone else.

## Install

```sh
curl -fsSL https://…/install.sh | sh     # or: sh install.sh --from plutonium-0.1.0-x86_64.tar.xz
plutonium doctor
```

It goes in `/opt/plutonium`, with no podman or checkout, and adds Plutonium to the login screen. On NixOS, the installer ends with a module to add to your configuration. `sh install.sh --uninstall` removes it and leaves your data. [INSTALL.md](https://github.com/ElSargo/plutonium-desktop/blob/v0.1.0/INSTALL.md) has the details.

## What's in it

- **Four shells,** installed in `~/.pluto/shells`. Run several at once and switch between them with Super+Tab:
  - **Styx:** scrollable tiling, after niri's design.
  - **Charon:** floating windows, with workspaces as threads, after GNOME Shell's design.
  - **Plain:** a minimal reference shell, and the safe mode (`plutonium run --safe`).
  - **Hydra:** coding agents, built on T3 Code.
- **Edit shells, or make your own.** A shell is a web app. Change one from the switcher (copy a prompt for your agent, or open a terminal), or make a new one. A change that breaks a shell is rolled back.
- **Apps and tabs side by side.** Apps get the GPU, keyboard, mouse, touchpad, fullscreen, pointer lock, and drag and drop. Each app and tab belongs to the thread or workspace that started it, and links opened from apps open as tabs next to them.
- **Agents.** An agent can list, launch, screenshot and drive its own thread's apps and tabs over MCP.
- **The desktop:** several monitors, the clipboard between apps and pages, screen sharing and screenshots (the desktop portal, grim), the file picker and printing for native apps, input methods (text-input-v3), global shortcuts, and H.264 video in tabs.
- **Runs on the hardware or in a window.** From the login screen or a text console, or in a window on your current desktop (`plutonium run --x11 :0`).

## Supported

x86-64 Linux with systemd and glibc 2.35 or newer, and an AMD or Intel GPU on Mesa.
- **Tested on:** NixOS with AMD graphics, the developer's machine. It has also run on real hardware with Debian and Fedora.
- **In containers only:** the release installs and starts on Ubuntu, Debian, Fedora, Arch and openSUSE.
- **Untested:** Intel should work. NVIDIA hasn't been tried, and its proprietary driver probably doesn't work.

## Known gaps

- The login screen entry hasn't been tried with a real display manager (GDM, SDDM, LightDM) yet. If it doesn't work with yours, start Plutonium from a text console (`plutonium run`), and please report it.
- There's no settings page for choosing an input method.
- Of the desktop portals, only screen capture, screenshots, global shortcuts, the file picker and printing are there. Notifications, settings and OpenURI aren't.
- Apps with a minimum size larger than their element (Firefox: 500 px wide) get clipped.
- The browser's DevTools are a Unix socket that only your own processes can connect to. That includes agents: Plutonium doesn't sandbox them from the rest of your account.
- [docs/BACKLOG.md](https://github.com/ElSargo/plutonium-desktop/blob/v0.1.0/docs/BACKLOG.md) has everything else that's known.

## If something goes wrong

- **If it hangs,** `plutonium stop --drm` over ssh ends it, and the text console comes back.
- **Logs** are in `~/.local/share/plutonium/logs`.
- **To report a bug,** open an issue with what you did, your distribution and GPU, the output of `plutonium doctor` and `plutonium status`, and those logs. INSTALL.md's "Reporting a bug" has the details. Check the logs before you attach them: they can contain page URLs and window titles.
